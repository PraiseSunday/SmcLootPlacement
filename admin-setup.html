SMC Loot Map — how this is put together

Reference notes for whoever's running this site. Not linked from the app itself.

The two pieces

GitHub Pages serves the static files (index.html, app.js, style.css, the chunked map data under data/) — that's it. It has no server-side logic, no accounts, no idea who's looking at the page. Every visitor gets the exact same files.

Supabase is the actual backend: a hosted Postgres database plus a realtime layer, talked to directly from the browser via @supabase/supabase-js. This is where pins, votes, and the admin login live.

How "admin" works

There's no connection between GitHub Pages and who's an admin. Signing in as admin means signing in to Supabase Auth through the "Admin sign-in" button in the app itself — that calls supabase.auth.signInWithPassword() with the email/password of the one Auth user created for this project. Supabase's JS client stores the resulting session in that browser's localStorage and the app checks for it on load (supabase.auth.getSession()) to decide whether to show delete buttons.

That means: it works the same everywhere — the live GitHub Pages site, a phone, a different computer — as long as you sign in with the same Supabase Auth credentials in that browser. Nothing about it is tied to GitHub, the repo, or how the site is hosted.

To change the admin password or add a second admin later: Supabase dashboard → Authentication → Users. Deleting a pin is gated by a Row Level Security policy tied to one specific user's UID (see below), so adding another admin means updating that policy too, not just creating another Auth user.

What's actually enforced where

ActionWho can do itEnforced by
Read pinsAnyoneDB policy (public select)
Create a pinAnyoneDB policy (public insert)
VoteAnyoneA Postgres function (increment_vote) — there's no public UPDATE policy on the table itself, so a vote can only ever change the votes column, never a pin's position/tier/note
Delete a pinAdmin onlyDB policy checking auth.uid() against the admin's UID — enforced by Postgres itself, not the app. The delete button is also hidden in the UI for non-admins, but that's just convenience; the real gate is server-side
Auto-delete at -10 votes—A database trigger, fires automatically on every vote, no app code involved

Full schema, policies, and trigger definitions: db/schema.sql in this repo.

Map data

The building geometry under data/chunks/ was extracted from the game's own mesh files and baked into a compact custom binary format (see tools/build_chunks.py) — it's a one-time export, not something the live site regenerates. If the source game data changes or the export pipeline improves, re-run that script and commit the new data/ contents.
